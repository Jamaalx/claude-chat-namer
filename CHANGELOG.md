# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.1.0] - 2026-11-01

### Added

- **Claude.ai and other Claude apps.** The skills fall back to Claude's own
  past-chat search there: find a chat and give its link, recap it into the
  current chat, suggest names to set from the chat menu. When past-chat
  search is not available, they say how to turn it on.
- **Native titles.** Claude Code now titles conversations itself (`ai-title`)
  and `/rename` stores your own title in the transcript. chat-namer shows
  them, in this order: `/rename` > your chat-namer name > Claude's title >
  compaction summary > first message. The tag says which one you see:
  `[renamed]`, `[named]`, `[ai]`, `[summary]`, `[auto]`.
- **`--all`** for `list`, `search`, `resume` and `recap`: every project at
  once, newest first, with the directory of each conversation
  (`--limit <n>`, default 40).
- **Full-text search.** `search` looks at everything you typed in a
  conversation, not only the first message. Every word must match, in any
  order; title hits rank first, content hits show a snippet.
- **`resume`** command (used by the `find` skill): the command now
  includes the directory (`cd <dir> && claude --resume <uuid>`), because
  `claude --resume` only finds a session from where it started. Outside
  Claude Code, `claude-chat-namer resume <query>` launches it directly.
- **`recap`** command and skill: pulls the last
  exchanges of an earlier conversation into the current one, so you can
  continue that work without resuming it.
- **`--json`** output for `list`, `search`, `resume` and `recap`.
- Respects `CLAUDE_CONFIG_DIR`.

### Changed

- **Just ask.** The six slash commands are now three skills Claude uses on
  its own when you talk about past conversations, in any language:
  `find` (replaces `list`, `search` and `resume`), `recap`, and `rename`
  (now also covers `auto-name`). They still work as `/chat-namer:find`,
  `/chat-namer:recap` and `/chat-namer:rename`.
- `rename` points to Claude Code's built-in `/rename` for the current
  conversation, so the name shows up in `claude --resume` too.
- Transcripts are streamed in 1 MB chunks instead of read whole, and the
  metadata is cached in `~/.claude/chat-namer/cache.json`. Transcripts are
  append-only, so a grown file is read only from where the last run stopped.
  On 8 GB of transcripts (577 conversations) the first `list --all` takes
  about 4 s; later runs about 0.3 s.

## [1.0.1] - 2026-09-24

Maintenance pass.

### Fixed

- `chat-names.json` is written atomically (temp file + rename). The Stop
  hook runs async, one per session; a reader that caught a half-written
  file parsed it as `{}` and the next save wiped every name in the project.
- Without `--project` the CLI, and so every `/chat-namer:*` skill, used
  whichever project directory came first instead of the one Claude Code is
  running in. It now resolves `CLAUDE_PROJECT_DIR` / the current directory
  (or its closest parent) first.
- Names written by the Stop hook or `auto` were shown as `[named]`; they are
  `[auto]` again, so `[named]` means a name you chose.
- Interactive mode: after a search, typing a number renamed the conversation
  with that number in the original list instead of the search hit.
- Interactive mode crashed on a non-numeric project choice.

### Changed

- `list` / `search` print the full UUID, so `/chat-namer:resume` can hand you
  a working `claude --resume <uuid>` command.
- `npm test` runs the smoke test; `prepublishOnly` runs it before a publish.
  `CHANGELOG.md` ships in the npm package.
- Dependabot checks npm and GitHub Actions monthly.

## [1.0.1] - 2026-08-30

### Fixed

- Plugin failed to load on current Claude Code (2.1.x) with
  `Hook load failed: Duplicate hooks file detected: ./hooks/hooks.json`.
  `hooks/hooks.json` is picked up automatically now, so the redundant
  `hooks` entry was removed from `.claude-plugin/plugin.json`.
- Sessions that start with a slash command (`/model`, `/login`, ...) were
  auto-named "Caveat: The messages below were generated by the user while...".
  The `isMeta` caveat line, `<command-name>` / `<local-command-stdout>`
  wrappers and subagent (sidechain) entries are now skipped, so the name
  comes from the first thing you actually typed.
- `list` showed raw `<command-name>...` names because the CLI did not strip
  tags the way the hook did. Transcript parsing and name generation now live
  in `scripts/index.js` and are shared by the CLI and the Stop hook.
- The Stop hook called `process.exit(0)` right after writing its JSON reply.
  On macOS/Windows a piped stdout is asynchronous, so the reply could be
  truncated. The hook now lets the process exit on its own.
- `name`, `unname` and `search` treated the value of `--project` as a
  positional argument (`name --project foo <uuid> <name>` looked for a
  conversation called "foo").
- The CLI header printed a hard-coded `v1.0.0`; it now reads the version
  from `package.json`.
- `getProjects()` no longer throws on a broken symlink inside
  `~/.claude/projects/`.

### Added

- `.claude-plugin/marketplace.json`: install with
  `claude plugin marketplace add Jamaalx/claude-chat-namer` followed by
  `claude plugin install chat-namer@claude-chat-namer`.
- CI on Node 18/20/22 (`node --check`, `npm pack --dry-run`, `test/smoke.sh`)
  and Dependabot for GitHub Actions.
- `test/smoke.sh`: end-to-end test of the CLI and the Stop hook against a
  throwaway `HOME` with fake transcripts.
- This changelog.

### Changed

- Author metadata is now "Alex Mantello" in `package.json` and `plugin.json`;
  `package.json` gained `repository`, `homepage` and `bugs`.

## [1.0.0] - 2026-03-19

### Added

- Initial release: `Stop` hook that auto-names conversations from the first
  user message, `/chat-namer:list`, `/chat-namer:search`, `/chat-namer:rename`,
  `/chat-namer:resume` and `/chat-namer:auto-name` skills, and a standalone
  CLI (`npx claude-chat-namer`). Zero runtime dependencies.
- Privacy policy (`PRIVACY.md`).
